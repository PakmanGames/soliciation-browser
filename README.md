# Solicitation Browser

_Full-Stack On-Site Programming Assignment_

## Overview

Every weekday, the U.S. Defense Logistics Agency posts hundreds of new Requests for Quotation (RFQs) to DIBBS, the Defense Internet Bid Board System, at [dibbs.bsm.dla.mil/RFQ](https://www.dibbs.bsm.dla.mil/RFQ/).
Each one is a public solicitation a vendor can bid on, usually for a specific part identified by an NSN (National Stock Number).

That's a lot of opportunities - but browsing DIBBS today is painful.
Vendors need a fast, focused way to scan recent RFQs and find the ones worth quoting on.

That's where you come in.
Your task is to build a tool that pulls daily DIBBS solicitations and lets a vendor browse, search, and filter them with ease.

This is an open-ended problem with no single "correct" solution.
We want to see how you think, how you approach an unfamiliar challenge, and how you make tradeoffs under time constraints.

## The Challenge

Build it your way.
Choose your own tech stack, architecture, and approach.
Create a full-stack web application where users can:

1. Pull data from `dibbs.bsm.dla.mil` - at minimum the **solicitation number** and **NSN** for each RFQ.
   More fields are welcome.
2. Browse the solicitations as a list or table.
3. **Search** across the solicitations.
4. **Filter** them - pick filters that make sense for someone evaluating opportunities.
5. Open each row back on its original page on DIBBS.

## What We're Looking For

- **UX, stability, and speed** - does it feel good to use?
- **Filter choices** - which filters you picked, and why.
- **Problem-solving** - your thought process in arriving at the solution.
- **Product sense** - whether it looks like something a vendor would actually want to use.
